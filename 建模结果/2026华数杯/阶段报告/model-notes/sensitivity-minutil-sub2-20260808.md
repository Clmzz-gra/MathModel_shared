## 1. 背景：A/B 空置的质疑

`sub2-region-load.pdf` 显示容量感知分配后 **A/B 区域承接 0 任务、负载率 0%**。用户提出：空置在各类意义下是否合理？是否反映建模不合实际？

### 1.1 现状核查结论（代码智能体已完成）

| 核查项 | 结论 |
|--------|------|
| 数据事实 | 总需求 5,020,787 GPU-hour，仅占 C/D/E/F 90% 阈值容量 8,618,400 的 **58%**（全局负载 ~40%）→ 容量充裕，无需启用 A/B |
| 目标一致性 | 成本最小化 + 容量感知（90% 阈值）→ 低价区（E/F）满载、高价区（A/B）闲置，是目标函数的正确输出 |
| 建模已知 | approach-sub2-confirmed.md §6 已记录"A/B 区空置"为已知风险，处置="论文论证：时延约束下实时任务留东部，容量闲置是可接受代价" |
| 时延约束 | A/B 来源实时任务迁往东部群内最便宜的 C（5–15ms ≤ 20ms SLA），未违规 |
| 假设边界 | 赛题 A1"迁移不建模带宽/能耗/费用"→ 迁移免费假设可能使空置程度比现实更极端 |

**结论：空置是模型内合理、现实部分合理的结果，不是代码 bug。** 但"0 承接"是极端边界，论文需主动论证 + 量化佐证。

### 1.2 用户疑问的回应

- 模型内：完全合理（成本最优的自然边界）
- 现实：部分合理，偏差来源 = 迁移免费假设 + 利用率非目标
- 论文角度：建议补**灵敏度/佐证分析**证明模型非病态

## 2. 提议方案：区域最低利用率灵敏度分析

### 2.1 方法

给 `capacity_aware_assign` 增加**保底承接参数**（`min_util: dict[region → 最低 GPU-hour 占比]`）：
1. 保底阶段：优先把候选含 A/B 的任务强制分派至 A/B，直至 A/B 承接达到 `min_util × Cap × 2400`
2. 常规阶段：剩余任务走现有容量感知贪心（90% 阈值 + 退路）
3. 层 2：每档保底比例走正式滚动窗 MILP（与 ε 分析同口径，数值可追溯）

### 2.2 档位与产出

| 档位 | A/B 最低利用率 | 说明 |
|------|---------------|------|
| 0% | 现状（缓存命中，秒级） | 基线 |
| 5% / 10% / 15% | 各 1 次新调度（~16 min/次） | 权衡曲线主体 |

**产出**：
- `figures/sub2-minutil-curve.pdf` — 最低利用率 vs 总成本曲线（0/5/10/15%，标注成本增量）
- `s2-results.pkl` 追加 `minutil_results`
- `tables/s2-results.tex` 新增表（利用率-成本权衡）
- manifest / charts 副本同步

### 2.3 时间成本

代码开发 30–40 min + 审查 10 min + 运行 ~50 min + 收尾 10 min ≈ **1.5–2 小时**。

## 3. 待建模智能体确认的事项

1. **是否采纳本方案**（新增灵敏度/佐证分析）
2. **保底口径**：按区域容量 GPU-hour 占比（推荐）还是任务数占比？
3. **保底区域**：A/B 同时保底（推荐，对称）还是仅 A？
4. **档位**：0/5/10/15% 四档是否合适，或需 20% 上限档
5. **论文叙事方向**：
   - 方向一：成本-利用率权衡曲线（让 A/B 开工 X%，代价 +Y%）
   - 方向二：空置合理性论证（0% 是成本最优边界，非模型缺陷）
   - 方向三：迁移免费假设的边界讨论（是否需要补充"若迁移有成本"的定性分析）
6. **是否同步讨论 S1 全局负载 40%**（容量充裕的另一佐证）
