## 2. 核心批判点（按严重度）

### 批判点 1【高】S3 域内 AUC 与 S1 域内 AUC 不一致，且 S3 未解释差异

**现象**：S1 报告（`iter-02-sub1-disease-prediction.tex` §4.1）与 S3 报告（`iter-02-sub3-cross-disease.tex` §6.1 衰减归因表）都声称给出「264 特征 L2+CLR 域内 AUC」，但数字不同：

| 疾病 | S1 报告 L2(CLR) AUC | S3 报告 domain_auc | 差异 |
|:--|:--:|:--:|:--:|
| CRC（Zeller） | 0.791 | 0.7811 | −0.010 |
| IBD（metahit） | 0.887 | 0.8588 | −0.028 |
| Obesity（Chatelier） | 0.650 | 0.6638 | +0.014 |

**pkl 佐证**：`S1-results.pkl` L2_CLR.AUC = 0.7907/0.8871/0.6496；`S3-results.pkl` domain_auc = 0.7811/0.8588/0.6638。两者确为不同值。

**为什么可能不成立（批判）**：S3 报告 §6.1 只声明「域内 AUC 为 264 特征 5 折 CV 重算，与跨疾病同口径」，并（在讲解包 §4.3）声明「不是 A3 的 1331 特征参考值（0.814/0.885/0.644）」，但**从未解释为什么与 S1 的 264 特征 L2 AUC（0.7907/0.8871/0.6496）也不同**。读者会困惑：同一个「264 特征 L2+CLR 域内 AUC」为何有两个值？S3 的衰减归因表（核心结论）引用的域内 AUC 与 S1 报告的域内 AUC 不一致，构成跨问数字矛盾。

**根因推断**：S3 approach §5 预处理多了一步 `StandardScaler`（均值/方差仅训练集估计），而 S1 approach §3 无此步骤。L2 正则化 Logistic 对特征尺度敏感，StandardScaler 会改变 L2 惩罚的生效方式，导致域内 AUC 与 S1 略有差异。S3 声称「沿用 S1 口径」（approach §1.2、报告 §2.1），但实际预处理比 S1 多一步 StandardScaler，**「沿用 S1 口径」的声明与实际实现不符**。

---

### 批判点 2【中】S3 报告 silhouette「未单独量化」与 approach/result-analysis 的 0.070 矛盾

**现象**：S3 approach §4.5 明确给出「silhouette 系数（数据集标签）= 0.070（近 0，不主导）」，S3 result-analysis §2.3 也引用「A 类验证 silhouette 0.070 近 0」。但 S3 报告 §6.1 写「silhouette 系数（数据集标签）未单独量化（本问数据为同一清洗管线，批次效应非主导，见待裁定项）」。

**为什么可能不成立（批判）**：approach 与 result-analysis 都已量化 silhouette=0.070，报告却写「未单独量化」，三者矛盾。这导致「批次效应不主导」这一归因结论在报告中**失去了定量证据支撑**（0.070 这个已量化的数字被报告丢弃，反而声称「未量化」）。三分法归因（批次效应/疾病特异信号/标签语义漂移）中「批次效应」一栏在报告里变成空口断言，削弱了归因的严谨性。

---

### 批判点 3【中】S3 声称「沿用 S1 口径」但多加了 StandardScaler（接口/假设冲突）

**现象**：S3 approach §1.2 与报告 §2.1 均声明「沿用 S1 已验证的模型口径（L2+CLR）」，但 S3 approach §5 预处理清单含 `StandardScaler`，而 S1 approach §3 求解方法表无 StandardScaler（仅 CLR 前置）。S2 亦无 StandardScaler。

**为什么可能不成立（批判）**：这是「接口复用」的隐性漂移——S3 复用 S1 的「L2+CLR」模型口径时，静默增加了一步 StandardScaler，导致 S3 的域内 AUC 与 S1 不一致（见批判点 1）。若 StandardScaler 是 S3 有意为之（为 LODO 跨疾病标准化），应在报告中显式声明「S3 在 S1 口径基础上增加 StandardScaler，故域内 AUC 与 S1 略有差异」，而非笼统说「沿用 S1 口径」后给出与 S1 不同的域内 AUC。

---

### 批判点 4【低】S2 文档「S1 主口径未选定」与 S1 已选定①归健康（时序矛盾）

**现象**：S1 result-analysis §3.3 已明确「推荐维持①（归健康）为主口径」，`selected_main_caliber='healthy'` 已落盘。但 S2 result-analysis T3 写「S1 主口径未选定（S1 2.2 未产出）」，S2 报告 §2.2 写「未选定前按题面口径归健康」。

**为什么可能不成立（批判）**：S2 的 T3 待裁定项「若 S1 改口径需重跑」实际上已可销项——S1 最终选定①归健康，与 S2 已执行的题面口径（归健康）一致，无需重跑。S2 文档保留了「S1 未选定」的过时信息，属时序矛盾（S2 合并时未回看 S1 已产出的 2.2 结论）。结果上无矛盾（都归健康），但文档表述需销项。

---

### 批判点 5【低】S3 approach 引用 S1 数字时混用 A 类验证值与正式值

**现象**：
- S3 approach §1.6 R1 写「S1 域内实测 RF 略优于 L2（Zeller 0.846 vs 0.812）」。0.846 接近 S1 正式 RF AUC 0.8454 ✓，但 0.812 是 S1 A 类验证 F2 的 L2 值（approach-S1 §6 F2），**不是 S1 正式 L2 AUC 0.7907**。
- S3 approach §6.2 衰减归因表用「CRC 0.814 / IBD 0.885 / Obesity 0.644」（A3 1331 特征参考值），而 S3 报告 §6.1 用 264 口径 0.7811/0.8588/0.6638。

**为什么可能不成立（批判）**：S3 approach 引用 S1 数字时，混用了「A 类验证参考值」与「正式落盘值」，且未标注来源口径。虽然 S3 讲解包 §4.3 已警告「不能混用域内 AUC 口径」，但 approach 文档本身残留旧值（0.812、0.814/0.885/0.644），与最终报告（0.7907、0.7811/0.8588/0.6638）不一致，属方案书与报告的口径漂移。

---

### 批判点 6【低】S3 approach 灵敏度 0.006 与报告 0.024（A 类验证 vs 正式实现）

**现象**：S3 approach §4.5/§6.4 写「C3 训练阈值迁移灵敏度 0.006」，S3 报告 §6.3 与 result-analysis §2.5 用 0.0244（正式实现）。0.006 是 A 类验证值，0.0244 是正式实现值，相差约 4 倍。

**为什么可能不成立（批判）**：approach 明确标注「A 类验证」参考值，正式以 pkl 为准，故不构成硬矛盾。但 0.006 → 0.024 的量级变化（4 倍）说明 A 类验证对 C3 阈值漂移的量化与正式实现有较大出入，approach 中「灵敏度 0.006」作为「标签语义漂移」的核心证据数字，与最终报告 0.024 的差异值得在报告中说明（A 类验证为何低估/高估）。

## 3. 一致项确认（无问题）

- **过滤口径**：三问均「近全零过滤 1331→264，三病并集统一口径」，pkl 佐证（S2 meta filter_threshold=0.95，S3 报告 264 特征）。
- **CLR 口径**：三问均 δ=6.5e-06 乘法替换 + 几何均值中心化，pkl 佐证（S1/S2/S3 meta clr_delta=6.5e-06）。
- **标签映射**：三问均患病=1/健康=0。
- **small_adenoma 结果口径**：三问最终均归健康（S1 selected_main_caliber='healthy'，S2 题面口径，S3 C1 测试 CRC n=121 含 small_adenoma）。
- **样本数/类别比例**：三问一致（Zeller 121/48 患病、metahit 110/25、Chatelier 253/164），S3 C1/C2/C3 测试集正类占比 39.7%/22.7%/64.8% 与 S1 少数类比例自洽。

## 4. 收束

三子问题在**数据口径层（过滤/CLR/标签）高度一致**，跨问矛盾集中在**数字引用层**：S3 复用 S1 的「域内 AUC」时，因静默增加 StandardScaler 导致数字与 S1 不一致且未解释（批判点 1/3，最高严重度）；S3 报告丢弃了已量化的 silhouette=0.070（批判点 2）；S2 文档残留「S1 未选定」过时信息（批判点 4）。这些均属「口径漂移/接口矛盾」，需在阶段 3.1 修正（详见 review-notes.md 修正建议）。
