# resources — 队友资源共享区

**这个目录是给队友用的，不受 PR 限制**：可以自由创建子目录、自由修改，直接 push。

> 核心原则：**链接优先，分类存放，登记全部写在 README**。避免把大文件塞进仓库（会让队友 pull 很痛苦）。

## 一、怎么用（3 步）

1. **放链接，不放文件**：能用链接表达的资源（插件、软件、工具网站、文章）**只登记链接**，不要上传原项目/原文件/软件本体
2. **按分类存放**：放进下面对应分类的目录；**如果新增了分类，记得同步把新分类加到这个 README**（见第四节）
3. **登记到 README**：不需要单独建说明文档，**直接在本文档对应分类的登记表里加一行**（链接 + 一句话说明 + 上传人）

## 二、基础分类

| 目录 | 放什么 | 怎么登记 |
|------|--------|---------|
| `插件项目/` | TRAE 等工具的插件（如 superpower） | 登记表：插件名 + 链接 + 作用 |
| `软件/` | 好用的软件 | 登记表：软件名 + 链接 + 用途；**不放软件本体**（安装包太大） |
| `工具网站/` | 在线工具、素材网站 | 登记表：网站名 + 网址 + 作用 |
| `文章/` | 值得一读的文章、教程 | 登记表：标题 + 链接 + 来源 + 一句话推荐理由；**不鼓励放原文** |
| `工作流/` | 自己的或网上找到的工作流程 | 可放文件，也可只登记链接；注明来源 |
| `领域知识/` | 某领域的知识整理 | **按领域建子目录**（如 `领域知识/概率统计/`），文件内注明来源 |

## 四、新增分类的规则

- 基础分类不够用时，**在 `resources/` 下新建目录**（如 `模板/`、`数据集/`）
- **同时**在本文档第二节的分类表加一行、在第三节加一个登记表小节——否则别人不知道有这个分类
- commit 信息写清楚，如 `资源: 新增"数据集"分类 + 上传 XXX 数据集链接`

## 注意

- 这里的内容**不会同步到队长的核心仓**，只在共享仓内流通
- **不要把临时文件塞进 `references/`、`latex/` 等共享目录**——那些是正式资产，会被同步走且受 PR 保护
- `resources/skills/math-explainer/` 是队长贡献的数学讲解 skill，**只读使用，不要修改**
