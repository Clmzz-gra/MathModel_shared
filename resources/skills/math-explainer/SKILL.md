# Math Explainer — 数学讲解辅助

## 激活条件

当用户请求涉及数学内容讲解（概念教学、定理推导、例题讲解、复习时的讲解）时激活。

## 讲解包模式（供队友写作前的技术理解）

**激活**：需要为队友生成技术讲解时——全局讲解包（00/01）在阶段 0-1 后生成；各问/方法讲解包在报告定稿（TRAE.md 阶段 2.4）后生成。

**输出**：`solution/handoff/` 下按序号命名的讲解包体系（不是单文件），结构见 `latex/templates/components/explain-pack.md`：
- `00-赛题内容与数据解析.md`（全局，1 个）：赛题转述 + 数据认知（字典/规模/口径/清洗），数字来自 `outputs/data/*.pkl` 或 `data-integration`。
- `01-整体分析逻辑与思路.md`（全局，1 个）：问题拆解、问间依赖、整体建模路线、阅读地图（各问文件与 M-xx 方法文件的对应表）。
- `02-问题N分析与思路.md`…（每问一个，编号 02 起递增）：该问的整体认知/来龙/主体/去脉/表述库指引五节。
- `M-xx-方法讲解-<方法名>.md`（每个方法一个，编号 M-01 起递增）：方法讲解五节，被多个问共用；首次用到该方法的问生成时创建，后续问直接引用「详见 M-xx」。

**与普通讲解的区别**：
- 受众是"要写论文但没做建模"的队友，不是复习的学生。术语可以出现，但每个术语首次出现必须给一句自然语言解释。
- 必须包含**可直接写进论文的结论句示例**（2-3 句），并标注哪些说法是过度承诺、不能写。
- 迷你算例必须能体现"数字从哪来"：给 1 个任务、1 个区域、2 个时段的最小实例，手动走一遍决策变量→目标→结果的流程。
- **必须包含「表述库指引」节**：从 `knowledge/expression-library.md`（已共享）按段挑出对应模板 ID 与例句（如 `5.1-48`、`2.2-20`、`3.2-33`），附"为什么适合本问"。parts 文件（暂不共享）的贴合原句**直接内嵌摘录**并注明出处，不要求队友访问 parts 文件。

**必须同步更新**：讲解包与内部报告的写作素材节保持同一组数字；数字来源均须可回溯（脚本/输出文件）。

**分两段生成（与报告分离）**：各问/方法讲解包在报告 `STATUS: done`、门禁 A 通过后**单独**生成，不随报告初稿捆绑产出；讲解包自身设门禁 B（人类审阅通过后才可交给队友写作）。全局讲解包（00/01）在阶段 0-1 完成后生成，供队友尽早建立整体认知。两段独立，保证各部分质量。

## 讲解质量约束

- **先定义再使用**：任何新符号、新概念必须在使用前给出明确定义，不得默认学生已认识；每个符号同时标明自然语言读法（如 $\forall$ 读作"对任意"，$\exists$ 读作"存在"，$\subset$ 读作"包含于"）
- **每步有"因为"**：推导的每一步都说明理由；先符号后数字，代入时标注具体数值
- **多视角**：用几何解释代数概念，用代数解释分析概念，用物理直观理解抽象
- **核心洞察收束**：讲解结尾用一句话收束核心思想
- **防跳跃**：讲解末尾标注可能需要展开的概念点（供后续追问）
- 若环境中存在相关 memory 规则（如 `explanation-quality.md`、`jump-prevention.md`），遵循之

## 知识脉络教学法 (Knowledge Pipeline)

一切章节教学遵循四层管线：**整体认知 → 来龙 → 主体 → 去脉**。

### 第一层：整体认知与框架

在学习任一科目的具体章节之前，先建立学科全景：

1. **数学史背景**：什么时代、什么核心问题驱动了这门学科的产生
2. **发展脉络**：学科如何演变，关键人物与转折点
3. **当代应用**：如今在科学、工程、经济等领域如何被使用

### 第二层：章节知识讲解

每一章的知识讲解严格按三个子步骤展开，顺序不可跳过：

#### A. 来龙 (Origins & Motivation)

在展示任何正式内容之前，先建立"为什么要学这个"：

| 来源 | 说明 | 示例 |
|------|------|------|
| **类比已知** | 连接到学生已有的知识 | "这和你在线性代数中学的特征向量是同一类思想" |
| **解决新问题** | 旧知识无法解决的问题，如何启发新概念 | "柯西需要一种方法计算有孤立奇点的积分" |
| **理论/应用需要** | 理论缺口或实践需求 | "为了量化测量误差，我们需要概率空间的理论" |

来龙部分无需用户交互，由讲解者主动铺设。

#### B. 主体 (Core Content)

数学主体内容的讲解。遵循以下约束：

- **逻辑顺序**：理清定义和定理的产生顺序——哪个先出现，哪个依赖哪个
- **跨学科理解**：用几何解释行列式含义，用代数解释分析概念，用物理直观理解数学抽象
- 遵循「讲解质量约束」中的全部规则

#### C. 去脉 (Applications & Extensions)

主体内容讲完后，展示知识的延伸价值：

1. **当代具体应用**：这个知识在现代解决什么具体问题，如何被使用
2. **跨领域解读**：这个知识能否用来理解其他领域或学科中的问题
3. **高层视角**：更高观点的理解与相关进阶内容（如 Taylor 展开 → Laurent 展开 → 留数定理 → 实积分计算，解决了数学分析中解决不了的问题）

## 例题讲解模式

### 若在当前章节教学流程中
- 例题应嵌入 主体 部分的讲解中，在讲完相关定理后立即展示
- 目的是巩固理论理解，不是孤立练习

### 若作为独立讲解请求
1. 先简要说明本题属于哪个知识体系（来龙，1-2句话）
2. 复杂内容写入临时 md 文件并用 VS Code 打开
3. 用分步推导：原始信息 → 公式代入 → 计算结果 → 结论
4. 每个计算步骤标注具体数值（示出代入的"因为"）
5. 结尾说明本题所用方法可以延伸到什么场景（去脉，1-2句话）
