## 2. 拐角解检测报告

- 方法：自由任务开工位置 = (开工 − 窗口最早) / (窗口跨度)，阈值 ±2%
- 结果：**45.2%**（171/378）任务开工在窗口边缘
- 判定：**未超 80% 阈值** → 不标记"拐角解主导"
- 解读：p10=0.00（10% 任务到达即开工）、p50=0.12（半数任务提前开工）、p90=0.94（10% 拖到最晚）→ 调度存在两极分化：实时敏感任务尽早、部分弹性任务延后削峰
- 区域差异：A 平均开工位置 0.15（早开工）vs B 0.45（居中）→ 容量充裕区域倾向于均衡排布

## 3. 未闭合问题清单

1. **拐角解 45.2% 的含义**：高比例边缘开工是否反映"容量宽松下的调度自由"还是"目标函数引导"？需在 2.2 后补开工位置分布图（敏感性讨论）
2. **均衡口径敏感性**：若改用方差口径，Alpha 会被 Beta 反超——论文叙事依赖极差口径选择，需做口径灵敏度（B 类已部分回答）
3. **预测提升空间**：白噪声证明下，是否存在更好的预测（如事件级到达建模）？当前不纳入，但论文需说明边界
4. **收尾时段负载**：22.4% GPU-hour 集中在 6h 收尾窗口——若任务更长/更多是否结清紧张？对 S2/S4 的收尾策略有启示

## 4. 实际落地检查

### 4.1 输入鲁棒性

- **核心输入 GPU_Demand**：任务声明值（1–127），实际执行可能波动。测试：±10% 需求扰动下容量余量仍 ≥50%（F3 全局负载 40% 佐证）→ 结论对输入误差不敏感
- **任务时长**：精确小数折算，实际可能超时 → 调度未留时长裕度（敏感性：时长 +10% 时拐角解是否恶化？待补）
- **预测输入**：S1 调度不用预测（赛题规定），预测误差不影响调度结果 ✅

### 4.2 输出成本

- **调度执行成本**：方案无经济成本（纯 GPU 排程，不涉及迁移/能耗——零迁移设定）
- **工程实现成本**：HiGHS 求解 472s/窗，若需实时重调度需缓存复用（perf 剖析已提供策略）
- **风险**：Beta 对比显示方差口径下贪心更优——若运营方实际关注方差而非极差，启发式可能更实用（论文须透明呈现）
